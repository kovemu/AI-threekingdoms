# Milestone 1 Implementation Plan

**Goal:** A zero-configuration Windows local-AI roleplay slice with atomic persistent turns.
**Architecture:** Preserve the existing TypeScript interfaces. TypeScript interprets and validates operations on a private draft; Rust owns managed inference, verified downloads and SQLite transactions. Publish the draft only after narration and SQLite commit succeed.
**Tech Stack:** Tauri 2, React, TypeScript, Vite, rusqlite, reqwest, llama.cpp.
**Spec:** `docs/GPT6_HANDOFF.md` and all existing docs.

The user explicitly authorized direct implementation and sensible decisions without another approval gate. This plan implements the existing approved architecture; it does not replace it.

## Global constraints
- Windows; primary target 8GB VRAM, 16GB RAM minimum.
- No accounts, API keys, external inference, Ollama, Python or provider settings for players.
- Manifest-based 7B–9B Q4 default, 3B–4B fallback; images disabled in this milestone.
- All-or-nothing operations and saved turns; model failures never commit partial state.
- Six locations, eight characters, four factions, a few armies.

## Review focus
- Model JSON invents IDs, impossible troop numbers, hostile army orders or direct capture.
- Valid first operation followed by invalid operation must roll back everything.
- Narrator or persistence failure and duplicate submissions must not advance the world.
- Partial/corrupt downloads must never be loaded; fallback must preserve the save.
- Restart must restore the exact world and narrative, with stale writers rejected.

## Tasks
1. Core (`src/core/{scenario,validation,projection,turn}.ts`, `tests/core.test.ts`): write rejection/rollback tests, run RED, implement strict schemas, rules, consequences, compact projection and serial turn engine, run GREEN.
2. Provider (`src/ai/local.ts`, `tests/provider.test.ts`): test JSON-only proposals, canonical narration and bounded projection. Implement the existing provider interface through a native inference bridge; scene unavailability falls back to board.
3. Native (`src-tauri/src/{lib,db,models,runtime}.rs`): test SQLite transaction/restart/stale write, hardware tier selection and checksum handling. Add Tauri configuration, manifest, streaming verified downloads, loopback managed llama-server, health checks and CPU/small-model fallback. Run cargo tests/build when toolchain is available.
4. UI (`src/App.tsx`, `src/style.css`): preparation progress, read-only large state area, narrative log, bottom input, retry errors and exact restore. Web-only execution explains desktop requirement and never pretends to run AI.
5. Verify and deliver: `npm test`, `npm run typecheck`, `npm run build`; native build/CI and clean-install smoke checks where available. Document exact evidence and limitations, commit and push feature branch.
